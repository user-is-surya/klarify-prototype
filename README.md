# Klarify prototype

**Sound alerts for people who can't hear them.** Klarify listens for important household sounds (a cooker whistle, a smoke alarm, a crying baby, the doorbell) and tells a hearing-impaired person with a loud, unmistakable visual alert on their phone.

This repository is the Review 2 hardware prototype from Team REVENANTS.exe (Design Thinking project). A laptop plays **synthetic** home sounds into an ESP32 over USB, the board **classifies them on the device**, and serves the alert to a phone page: full-screen colour, vibration, and a history log.

> **Simulated input.** There is no microphone yet. Every sound is generated by software, and every accuracy figure below was measured on synthetic sounds only. These are not real-world results. The firmware has been compiled and its core logic tested on a PC, but it has **not yet been run on a real board**. [docs/trial-checklist.md](docs/trial-checklist.md) is that first run.

## How it works

```
Laptop (Python)                 ESP32 (Arduino / PlatformIO)                  Phone browser
tools/sounds.py                 serial reader -> 1 s window -> features       portal served by the ESP32
tools/feed.py   --8 kHz PCM-->  -> decision tree -> 2-in-a-row rule -->       polls /api/state
(keys pick a sound,   USB       -> alert state + LED pattern                  (colour, icon, history, mute)
 noise level, playlist)         Wi-Fi access point "Klarify-Demo"
```

1. **Generate.** `tools/sounds.py` synthesises five household sounds plus background noise, with random pitch, level and noise, at a controllable signal-to-noise ratio.
2. **Stream.** `tools/feed.py` sends 8 kHz, 16-bit mono audio over USB serial at 921600 baud, in real time, in 50 ms blocks. Each frame carries a sync header, a sequence number and an XOR checksum so the board can resync after a glitch ([tools/protocol.py](tools/protocol.py)).
3. **Classify on the board.** The ESP32 keeps a 1 s window (hop 0.5 s), runs its own radix-2 FFT (no library), extracts 10 spectral and timing features, and walks a small decision tree. The board does the classifying; the laptop is only a sound source.
4. **Debounce.** An alert fires only after **two matching classifications in a row**, so one stray blip doesn't cause a false alarm. Expect the phone to react 1-2 seconds after a sound starts.
5. **Alert.** The board runs its own Wi-Fi access point, so the demo needs no internet. The phone joins `Klarify-Demo`, opens `http://192.168.4.1`, and the page polls the board every ~300 ms.

When a real I2S microphone is added later, it replaces one function (the audio source); nothing downstream changes.

### Sounds and alert levels

| Sound | Level | Portal colour | Board LED (GPIO2) |
|---|---|---|---|
| Smoke alarm | Urgent | Red | Fast continuous blink |
| Cooker whistle | Urgent | Red | Fast continuous blink |
| Baby crying | Important | Amber | Two blinks |
| Doorbell | Info | Blue | One blink |
| Microwave beep | Info | Blue | One blink |
| Background | None | Dark "Listening..." | Off |

The portal also shows the sound's name and icon, the time, a history list, a per-sound **mute** (muted sounds stay in the history, struck through), a note when the feeder isn't running, and a **"No signal"** panel if the board stops responding, so a lost connection never leaves a stale red screen. Vibration uses the browser Vibration API: Android Chrome after one tap; iPhone shows colour only.

Audio never leaves the ESP32. Only the sound's name goes to the phone.

## Just want to run it?

1. Download `klarify-demo.zip` from the **Releases** page and unzip it.
2. Follow the `README.txt` inside: run `flash.bat` once, join the `Klarify-Demo` Wi-Fi on a phone, open `http://192.168.4.1`, and run `klarify-feeder.exe`.
3. Press `1`-`5` to play a sound, `0` for background, `+`/`-` for more or less background noise, `a` for a hands-free auto playlist, `q` to quit.
4. Before any demo, do the 10-minute trial in [docs/trial-checklist.md](docs/trial-checklist.md).

You need a Windows laptop with the CP210x USB driver, the ESP32 board with a **data** USB cable (many cables are charge-only), and a phone. The release bundles everything else: no Python, no installs. If antivirus blocks `klarify-feeder.exe`, the zip also contains a `python-fallback` folder.

## Updating over Wi-Fi (OTA)

From v1.2 the firmware can update itself over Wi-Fi. A board running v1.1 or older has no OTA code, so flash v1.2 over USB once with `flash.bat`.

After that: join the `Klarify-Demo` Wi-Fi, open `http://192.168.4.1/update`, enter the update password (`klarify`), choose `klarify-ota.bin` and tap **Install update**; or run `update.bat` from the kit on a laptop. The board restarts by itself and the portal footer shows the new version. Use `klarify-ota.bin` (the app image, also attached to each release), not `firmware.bin`, which is the full USB image; the board refuses it. The password only stops casual mistakes on the open demo hotspot and is not strong security. The OTA path has been tested against a simulated board and its partition layout checked, but has not yet run on a real board (see [docs/trial-checklist.md](docs/trial-checklist.md), steps 12-15).

## Measured results (synthetic data only)

A decision tree (depth 8) trained on 1500 generated clips per class and tested on freshly generated held-out clips with different random seeds:

| Held-out test condition | Accuracy |
|---|---|
| SNR 10-30 dB | 98.8% |
| SNR 6 dB | 96.8% |
| SNR 3 dB (very noisy) | 95.8% |

Per-class recall at 10-30 dB is 100% for cooker whistle, smoke alarm and microwave beep, 99.8% for baby cry, 99.0% for doorbell and 96.3% for background. Reproduce with `python tools\train.py`, which prints the full confusion matrix. Because the training and test sounds come from the same generator, these numbers say the pipeline works, **not** that it will work in a real kitchen. At the noisiest feeder settings the board will occasionally mix sounds up; that is expected and worth saying out loud.

## Build from source

**Requirements:** Windows, Python 3.13, [PlatformIO](https://platformio.org/) (installed by the requirements file below), and MSYS2 `g++` (for the native C++ tests; found on `PATH` or at `C:\msys64\ucrt64\bin`).

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pytest
.venv\Scripts\python tools\build_release.py
```

- `pytest` runs 78 tests (about 100 seconds) covering the generator, features, training, the serial protocol, the feeder, port detection, the portal, the release build, and the C++ core compiled natively with `g++`.
- `tools\build_release.py` embeds the portal, builds the firmware with PlatformIO, merges a flashable `firmware.bin`, builds `klarify-feeder.exe` and `esptool.exe` with PyInstaller, and writes `dist/klarify-demo.zip`.

### Everyday commands

| Task | Command |
|---|---|
| Retrain the model and regenerate `firmware/include/model.h` | `.venv\Scripts\python tools\train.py` |
| Re-embed the portal page after editing `firmware/portal/index.html` | `.venv\Scripts\python tools\embed_portal.py` |
| Compile the firmware | `.venv\Scripts\pio run -d firmware` |
| Preview the portal with no board (scripted fake state) | `.venv\Scripts\python tools\mock_portal_server.py --port 8080` |
| Check the board link (expects `OK klarify-fw 1.2`) | `.venv\Scripts\python tools\feed.py --selftest` |
| Run the feeder against a board on a specific port | `.venv\Scripts\python tools\feed.py --port COM5` |
| Run a scripted sequence | `.venv\Scripts\python tools\feed.py --script "doorbell:8,background:4"` |

`feed.py` also accepts `--auto`, `--noise-level 0..5`, `--seed`, and `--sim <path to sim_device.exe>` to talk to a PC simulator of the firmware core instead of a board.

## Repository layout

```
firmware/            PlatformIO project for the ESP32 (esp32dev, Arduino, C++17)
  include/core/      portable core: FFT, features, classifier, alert rule, state, LED, protocol
  include/model.h    GENERATED decision tree (tools/train.py), do not edit
  include/portal.h   GENERATED from portal/*.html (tools/embed_portal.py), do not edit
  portal/index.html  the phone page
  portal/update.html the over-the-air update page
  src/main.cpp       Wi-Fi access point, web server (/, /update, /api/state, /api/mute, /api/version), serial input
tools/               sounds, dataset, features, train, feed (the CLI), protocol, release build
tests/               pytest suite plus native C++ tests (tests/native/)
release/             README.txt, flash.bat and update.bat that ship inside the demo zip
docs/                trial checklist, design spec, implementation plan
```

The core in `firmware/include/core/` has no Arduino includes, which is why it can be compiled and tested natively on a PC. The Python and C++ feature code is checked for parity.

## Not in this prototype

Real microphone (INMP441), smartwatch / BLE, water probe and tank-overflow sound, user-taught sounds, cloud or messaging alerts, real-world accuracy claims, battery and enclosure. These are planned for later reviews.
