KLARIFY - DEMO KIT (Design Thinking, Review 2)
===============================================
Team REVENANTS.exe

What this is
------------
A laptop plays SYNTHETIC household sounds (generated by software, not recorded) to an ESP32 over
the USB cable. The ESP32 itself works out which sound it is and shows a colour alert on a phone.
No microphone yet - that comes in a later review. Say "simulated input" when you present.

You need
--------
- Windows laptop with the CP210x USB driver (already installed)
- The ESP32 board + a DATA USB cable
- A phone (Android shows a vibration button; iPhone shows colours only)

Step 1 - flash the board (once)
-------------------------------
Plug the ESP32 in, then double-click  flash.bat
Wait for "DONE".

Step 2 - check the link (10 seconds)
------------------------------------
Open a terminal in this folder and run:   klarify-feeder.exe --selftest
You should see:   OK klarify-fw 1.0

Step 3 - open the portal on the phone
-------------------------------------
Phone Wi-Fi settings -> join "Klarify-Demo" (no password).
If the phone says "no internet", choose STAY CONNECTED / turn off "switch to mobile data".
Open the browser and go to:   http://192.168.4.1
Android: tap "Tap to enable vibration" once.

Step 4 - play sounds
--------------------
In the terminal:   klarify-feeder.exe
Keys:   1 cooker whistle (red)     2 doorbell (blue)      3 baby crying (amber)
        4 smoke alarm (red)        5 microwave beep (blue)
        0 stop / background        + / - more / less background noise
        a auto playlist (hands-free demo)     q quit
Each sound plays for 10 seconds, then the room goes quiet again.
Expect the phone to react 1-2 seconds after a key press (the board needs 2 matching
half-second checks in a row before it alerts, so one stray blip does not cause a false alarm).
The small blue LED on the board also blinks: urgent = fast, important = two blinks, info = one.

Mute test: on the phone tick a sound under "Mute a sound" - it stops alerting but still appears
in the history, struck through.

Updating later without USB (over Wi-Fi)
----------------------------------------
The first time, flash this version with USB (Step 1). After that, new versions can be installed
over Wi-Fi - no cable needed:
  1. Download the new kit and unzip it on the laptop or phone.
  2. Join the "Klarify-Demo" Wi-Fi (this cuts the internet, so download first).
  3. EITHER open  http://192.168.4.1/update  in a browser, type the password, choose
     klarify-ota.bin, tap "Install update"
     OR on the laptop double-click  update.bat  (it sends klarify-ota.bin from the same folder).
  4. Wait about 10 seconds. The board restarts by itself. The portal footer shows the version.
Password: klarify   (it only stops casual mistakes on the open demo Wi-Fi - it is not strong security).
Use klarify-ota.bin here. firmware.bin is the USB image and the board will refuse it.
Keep the board plugged in during the update; do not unplug it until the portal comes back.

If something goes wrong
-----------------------
- "No ESP32 found": different USB cable (many are charge-only) / other port. Device Manager must
  show a USB serial device under Ports (CP210x or CH340, depending on the board). If it shows
  up there but the feeder still cannot find it, give the port yourself:
      klarify-feeder.exe --port COM5      (use the number Device Manager shows)
- Update refused: wrong password, or you chose firmware.bin instead of klarify-ota.bin.
- Flashing will not connect: hold the BOOT button while flash.bat says "Connecting....".
- Antivirus blocks klarify-feeder.exe: use the Python version in the python-fallback folder:
      pip install numpy pyserial
      python feed.py
- Portal shows "Reconnecting..." and the big panel says "No signal": the phone left the
  Klarify-Demo Wi-Fi, or the board lost power (the USB cable is its only power - unplugging it
  switches it off). Rejoin the Wi-Fi / plug the board back in; it recovers by itself.
- Portal shows "Input idle": the board is fine but the feeder is not running (or was closed).
  Start klarify-feeder.exe again.
- The feeder says the port is busy: close the Arduino IDE / any serial monitor.

Honest notes for the panel
--------------------------
- All sounds are synthetic. Any accuracy we quote is on synthetic sounds, not real kitchens.
- The "+" key makes the background noisier. At the two noisiest settings the board can mix sounds
  up now and then; that is expected and worth saying out loud.
- The audio never leaves the ESP32 - only the sound's name goes to the phone page.
